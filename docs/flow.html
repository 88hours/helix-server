Helix

From production crash to merged fix — automatically

🚨
Trigger

A crash happens in production

Sentry detects an error (e.g. a 500, an unhandled exception) and sends Helix a notification within seconds.

🔍
Agent 1 — Crash Handler

Understand the crash

AI reads the raw error, stack trace, and context, then produces a structured summary: what broke, where, how severe, and what it was doing at the time.

AI-powered Severity rating Plain-English summary
🧪
Agent 2 — QA Agent

Open a ticket & write a failing test

Creates a GitHub issue, reads the relevant source code, then writes a test that proves the bug exists. The test is designed to pass once the fix is applied — not before.

GitHub issue created Reads source code Writes failing test

Duplicate

Notify team — skip re-run

The same bug has already been seen. Helix pings Slack to remind the team there's a fix PR waiting for review instead of starting over.

Agent 3 — Dev Agent

Write & verify the fix

AI writes the minimum code change to make the test pass, then runs the entire test suite to confirm nothing else broke. Posts the fix idea to the GitHub issue first so there's always a human-readable audit trail.

PR opened on GitHub

A pull request is created with the fix, the new test, and a plain-English description of what changed and why.

Escalation

Human escalation via Slack

Helix sends a full context dump — crash, test, and all 3 failed attempts — so a developer can pick up exactly where it left off.

A reviewer gets an Approve / Reject message in Slack with a link to the PR. One click is all it takes. Nothing merges without a human sign-off.
