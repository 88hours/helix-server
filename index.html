Helix is an autonomous incident response platform. It takes a crash from Sentry or Rollbar, writes a failing test, fixes the bug, opens a pull request, and waits for your Slack approval before merging.

How it works

Four agents. One human approval. Zero manual steps.

01

Crash Handler

Receives Sentry or Rollbar webhooks, classifies severity, detects the application language, and produces a structured crash report.

02

QA Agent

Deduplicates against open GitHub Issues. If it's a known bug, skips the pipeline and notifies Slack. Otherwise, clones the repo and generates a failing test that asserts correct behaviour — not that the crash occurs.

03

Dev Agent

Posts a fix suggestion to the GitHub Issue, then runs a full TDD loop: clones the repo, runs the failing test, writes the minimum fix, and verifies the full suite. Retries up to 3 times. On success, opens a pull request.

04

Notifier Agent

When a PR is ready, posts an Approve / Reject message to Slack. Sends escalation alerts with full context if the Dev Agent exhausts all retries. All notifications are optional — the pipeline continues without Slack or email configured.

05 — Human approval

You approve or reject in Slack

Click Approve & Merge to merge the PR automatically, or Reject to leave it open for manual review. Nothing reaches production without your sign-off.

Built for real codebases

Not a toy. Every decision was made to handle production crashes reliably.

🧪

Correct-behaviour tests

The QA Agent writes tests that assert what the function should return, not that the crash occurs. Validated and retried if wrong.

🌐

Multi-language

Python, JavaScript, TypeScript, Ruby, Java, Kotlin, and Go. Stack trace parsing, test generation, and fix commands are all language-aware.

🔁

TDD loop with retries

The Dev Agent runs the failing test, writes a fix, runs the full suite, and retries up to 3 times. Each retry learns from previous failed attempts.

✅

Human approval gate

Every fix requires a human to approve via Slack before the PR is merged. Approve & Merge or Reject — nothing reaches production automatically.

🎫

Smart deduplication

The QA Agent checks open GitHub Issues before running the pipeline. If the bug is known, it skips straight to a Slack notification and prompts you to approve any pending PR.

📡

Sentry + Rollbar

Receives webhooks from both Sentry and Rollbar. Signature-verified on every request. Demo mode skips verification for local testing.

🔔

Optional notifications

Slack and email (SendGrid or SMTP) are fully optional. Missing config is logged as a warning — the pipeline never stops for a missing token.

💾

Redis Streams

Events are persisted in Redis Streams — messages survive agent restarts and are never silently lost. Falls back to Pub/Sub for legacy setups.

🚀

One-command deploy

Deploy all four agents to Railway in one command. Sync your .env file directly to Railway with --env-file.

Get started in minutes

Local Docker setup or one-command Railway deploy.

Local setup requires Docker 
# 1. Clone and install
git clone https://github.com/88hours/helix
cd helix && uv sync --extra dev

# 2. Configure
cp .env.example .env
# fill in ANTHROPIC_API_KEY, GITHUB_TOKEN, SENTRY_WEBHOOK_SECRET or ROLLBAR_ACCESS_TOKEN

# 3. Run (Redis starts automatically)
docker compose up --build
OR
Railway deploy requires Railway CLI 
# Deploy all four agents with env vars in one command
./railway-deploy.sh --env-file .env
Required: ANTHROPIC_API_KEY · GITHUB_TOKEN · SENTRY_WEBHOOK_SECRET or ROLLBAR_ACCESS_TOKEN · REDIS_URL
Optional: SLACK_BOT_TOKEN · SLACK_SIGNING_SECRET · SLACK_APPROVAL_CHANNEL · SENDGRID_API_KEY · SMTP_HOST
